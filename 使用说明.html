DSH 完成任务音效 · 使用说明

版本 1.1.0 ｜ 2026-11-08 ｜ 适用于 Windows 桌面版 DeepSeek Harness

每轮对话跑完响一声。音效可换、音量可调，也能换成你自己的音频。

一、装之前先看这两条

  1. 需要桌面版 DeepSeek Harness（Windows）。只要 Web 界面能正常打开就行，不用装 Node、不用装依赖 —— 这个插件本身零依赖。
  2. 装完先在页面里随便点一下（点空白处、点输入框、按一下键盘都算）。浏览器规定"没有用户操作就不许出声"，点这一次之后就一直有效。不点的话，第一轮跑完可能没有声音，别误以为装坏了。

二、安装

方法一：让 DSH 自己装（推荐）

  1. 拿到插件文件夹，三选一： - 从 GitHub 下载 ZIP：<https://github.com/huanyuan6657-cmd/dsh-completion-sound> → Code → Download ZIP，解压； - 从朋友那里拿到的 dsh-completion-sound-1.2.0.zip，解压； - 有 Git 的话直接 git clone https://github.com/huanyuan6657-cmd/dsh-completion-sound.git。 把解压出来的 dsh-completion-sound 文件夹放到一个固定的地方，比如 D:\dsh-plugins\。路径里尽量别有空格和中文，能省掉一堆麻烦。
  2. 在 DSH 的对话框里发一句话（把路径换成你实际解压的位置）：
    用 plugin_manager 把这个插件装上：D:\dsh-plugins\dsh-completion-sound
  3. 回执里出现 "application": "applied" 或 "installed": true 就成功了，刷新一下页面。

方法二：更新已装的版本

用新文件夹覆盖旧文件夹，然后在「设置 → 插件」里把它关掉、再打开一次（或者重启 DSH）。 原因是宿主那一半代码（index.js）有模块缓存，不重挂一次还是旧的；界面那一半（client.js）改完会自动热加载，不用管。

方法三：手动装（不推荐，容易出错）

把 dsh-completion-sound 文件夹复制到：

C:\Users\<你的用户名>\.dsh\profiles\desktop\node_modules\

再打开同目录上层 .dsh\profiles\desktop\package.json，在 dsh.profile.bundles 数组里加一行：

"dsh-completion-sound"

保存后重启 DSH。

三、开始用

打开 设置 → 完成任务音效（排在「宠物设置」和「插件市场」之间）。

控件说明
开启提示音总开关。关掉后完全不响，也不占音频设备；同时会自动解除下面的「屏蔽」
前台也播放提示音开着：任何时候跑完都响。关掉：只有窗口不在前台才响（盯着屏幕时不打扰，去干别的才提醒）
屏蔽其他提示音开着：把同一页面里其他插件（比如鲸鱼小组件）播的完成音一起静音，只剩这一声。关掉就恢复原样
音效九宫格点一下即试听并保存，当前生效的那个会高亮
音量拖动时实时改，松手试听一次
自定义音频上传本地文件或填网络直链，「清除」回到内置音效

七个内置音效：清脆铃、上扬、柔和钟、木质敲击、水滴、短提示、小号角。 它们是用 WebAudio 现场合成的，插件里不带音频文件，所以整个包只有 100 多 KB。

四、换成自己的声音

  • 上传文件：点「选择文件」，支持 mp3 / wav / ogg / m4a / aac / flac / webm，不超过 8 MB。
  • 用直链：把 https://…/ding.mp3 这样的地址粘进去，适合放在自己的图床或网盘直链上。
  • 恢复内置：点任意一个内置音效，自定义音频会被自动清掉。

自定义音频存在本地，不上传、不外发。

五、那个"叮咚"是哪来的？

先说明一点：DSH 本身不带完成任务音效。我把它 182 MB 的主程序（以及全部内置插件）翻过一遍：没有任何音频素材，也没有 new Audio、playSound、SystemSounds、MessageBeep 这类播放代码，唯一的系统通知只服务于"强制更新就绪"。所以每轮结束那第二声，一定来自页面里某个第三方插件。

最常见的是鲸鱼小组件（dsh-whale-widget，右下角那只）：它的「每轮消耗」提示音出厂就是开着的，每轮结束响 1.3 秒——就是那声"叮咚"。

三个办法，任选：

  • A（省事）：留着本插件的「屏蔽其他提示音」（默认开）。它会把页面上其他插件三条发声路径全堵住——远端音频请求、已解码的 AudioBuffer 播放、以及 <audio>/<video>/new Audio()——所以你只听到本插件这一声。
  • B（彻底）：点右下角小鲸鱼 → 「每轮消耗」那一行 → 点齿轮/铅笔进「自定义提示」→ 取消「任务结束音」左边的 [✓] → 保存。这是改鲸鱼自己的设置，重启、升级都不反弹；余额和气泡提示不受影响，只是不出声。
  • C（查明真相）：保持屏蔽开着跑一轮，然后看诊断：http://127.0.0.1:<你的端口>/dsh-completion-sound/diag。里面每条 buffer-blocked / fetch-blocked 都带调用栈，能直接指出是哪个脚本在发声。

如果 A 开着、/diag 里却一条拦截记录都没有，那这声音就不来自页面（多半是 Windows 的通知音、耳机提示音或别的软件），本插件管不到，可以从系统声音设置里关。

六、什么时候会响，什么时候不响

会响：

  • 一轮对话正常跑完（中途被你打断、报错中断的那种不算）。

不会响：

  • 子代理/子任务跑完（只有主会话算，不然一个任务派 5 个子代理就响 5 次）。
  • goal 模式自动续跑的中间轮（只在全部结束时响一次）。
  • 刷新页面、重启 DSH 之后，不会把历史轮次补响一遍。

七、没声音？按这个顺序查

  1. 页面里点一下（解锁音频，见第一节第 2 条）。
  2. 设置里「开启提示音」是不是关着。
  3. 「前台也播放提示音」是不是关着 —— 关着的时候，只有窗口不在最前面才会响。
  4. 系统音量、输出设备、浏览器标签页有没有被静音。
  5. 换个内置音效点点看（能听到试听声说明音频链路是好的）。
  6. 设置页最底下有一行状态：显示宿主联系正常、最近一次触发的时间，可以用来判断是"没触发"还是"没出声"。

八、卸载

在对话里说：

用 plugin_manager 把 dsh-completion-sound 卸掉

或者去「设置 → 插件」里关掉它。配置和自定义音频会留在 C:\Users\<你>\.dsh\dsh-completion-sound\，想彻底清干净就手动删掉这个文件夹。

九、它把你的东西存在哪

内容位置
设置C:\Users\<你>\.dsh\dsh-completion-sound\config.json
自定义音频同一目录下 custom.<扩展名>

存在本地磁盘而不是浏览器缓存，所以换端口、清浏览器缓存、换浏览器都不会丢。

联网情况：不联网。插件只在自己的电脑上开了一个本地接口（127.0.0.1），用来和页面对接；不收集任何数据。

十一、已知限制

  • 只在 Windows 桌面版验证过；其他平台理论上一样，但没实测。
  • 第一次用必须有一次点击/按键，这是浏览器的硬性规定，绕不过去。
  • 页面切到后台很久时音频引擎会主动挂起（省电，也避免阻止系统休眠），切回来自动恢复。
  • 屏蔽其他提示音是"页面级"的：屏蔽期间，同一页面里其他插件用 WebAudio 播的声音也会一起没声。这是有意为之的取舍。
